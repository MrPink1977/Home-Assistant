# Custom Wake Word Training for HAVoice PE

This guide walks you through creating a custom wake word for your Home Assistant Voice PE device using the microWakeWord framework and Jupyter notebook.

## Overview

The microWakeWord framework uses TensorFlow to train wake word detection models that run on low-power ESP32 devices. Training uses synthetic voice samples generated by Piper TTS, optionally combined with your personal voice recordings.

## Prerequisites

- **Python 3.10** (required - not compatible with 3.11+)
- **8GB+ RAM** (16GB recommended for training)
- **5GB+ free disk space**
- **NVIDIA GPU** (optional but recommended for faster training)

## Quick Start

### Option 1: Docker (Recommended)

The easiest way to get started is using Docker:

```bash
# Pull the training container
docker pull ghcr.io/futureproofhomes/microwakeword:latest

# Run with Jupyter notebook
docker run --rm -it \
  -p 8888:8888 \
  -v $(pwd)/microwakeword_training:/workspace \
  ghcr.io/futureproofhomes/microwakeword:latest \
  jupyter notebook --ip=0.0.0.0 --allow-root --no-browser

# With GPU support (NVIDIA)
docker run --rm -it --gpus all \
  -p 8888:8888 \
  -v $(pwd)/microwakeword_training:/workspace \
  ghcr.io/futureproofhomes/microwakeword:latest \
  jupyter notebook --ip=0.0.0.0 --allow-root --no-browser
```

Open `http://localhost:8888` in your browser and use the token shown in the terminal.

### Option 2: Local Installation

```bash
cd microwakeword_training
chmod +x setup_training_env.sh
./setup_training_env.sh
```

Then start Jupyter:

```bash
source microwakeword_venv/bin/activate
jupyter notebook
```

## Step-by-Step Training Guide

### Step 1: Prepare Personal Voice Samples (Optional but Recommended)

Recording your own voice samples significantly improves accuracy:

1. **Create recordings** of yourself saying your wake word
2. **Record 10-30 samples** with variations:
   - Different distances from microphone
   - Different volumes (whisper, normal, loud)
   - Different speaking speeds
   - Different emotional tones
3. **Save as WAV files** (16-bit, 16kHz mono recommended)
4. **Place in** `microwakeword_training/samples/personal/`

**Naming convention:**
```
hey_freya_01.wav
hey_freya_02.wav
hey_freya_03.wav
...
```

### Step 2: Configure Training

Edit `config/training_config.yaml`:

```yaml
wake_word:
  phrase: "hey_freya"        # Your wake word
  preset: "medium"           # short/medium/long

samples:
  synthetic_count: 10000     # More = better but slower
  use_personal_samples: true

augmentation:
  level: "medium"            # light/medium/heavy

training:
  epochs: 100
  batch_size: 64
```

### Step 3: Run Training

1. **Open Jupyter Notebook:**
   ```bash
   jupyter notebook
   ```

2. **Navigate to** `notebooks/easy_training_notebook.ipynb`

3. **Configure the wake word** in the first cell:
   ```python
   WAKE_WORD = "hey_freya"
   OUTPUT_DIR = "../models/hey_freya"
   USE_PERSONAL_SAMPLES = True
   PERSONAL_SAMPLES_DIR = "../samples/personal"
   ```

4. **Run all cells** (Shift+Enter or Run All)

5. **Wait for training** (15 minutes to several hours depending on settings)

### Step 4: Evaluate the Model

After training, the notebook will show:

- **Accuracy metrics**
- **False positive/negative rates**
- **Audio samples for testing**

Test the model with:
```python
# In the notebook
model.test_detection("path/to/test_audio.wav")
```

### Step 5: Export Model Files

Training produces two files needed for your Voice PE:

1. **`hey_freya.tflite`** - The TensorFlow Lite model
2. **`hey_freya.json`** - Model manifest with metadata

```json
{
  "name": "hey_freya",
  "version": "1.0.0",
  "model_file": "hey_freya.tflite",
  "probability_cutoff": 0.85,
  "sliding_window_size": 5
}
```

## Deploying to Voice PE

### Step 1: Copy Model Files

Copy the trained model to your Home Assistant configuration:

```bash
# Local deployment
cp models/hey_freya/hey_freya.tflite ../config/custom_wakewords/
cp models/hey_freya/hey_freya.json ../config/custom_wakewords/

# Or for Windows host
cp models/hey_freya/hey_freya.* /mnt/c/AI_Projects/homeassistant/config/custom_wakewords/
```

### Step 2: Update ESPHome Configuration

Edit your Voice PE configuration (`voice-pe-config-template.yaml`):

```yaml
micro_wake_word:
  models:
    - model: /config/custom_wakewords/hey_freya.json
      id: hey_freya
      probability_cutoff: 0.85
      sliding_window_size: 5
    # Remove default wake words to save memory
    - id: !remove hey_jarvis
    - id: !remove alexa
```

### Step 3: Flash Voice PE

1. Open ESPHome dashboard in Home Assistant
2. Select your Voice PE device
3. Click **Install** → **Wirelessly**
4. Wait for OTA update to complete

### Step 4: Select Wake Word in Home Assistant

1. Go to **Settings** → **Voice assistants**
2. Edit your voice assistant
3. Select **"Hey Freya"** from the wake word dropdown
4. Save

## Tuning Detection Sensitivity

If your wake word isn't working well, adjust these parameters:

### Too Many False Positives (triggers incorrectly)

```yaml
probability_cutoff: 0.90      # Increase (range: 0.85-0.95)
sliding_window_size: 7        # Increase (range: 5-10)
```

### Too Many False Negatives (doesn't trigger)

```yaml
probability_cutoff: 0.70      # Decrease (range: 0.50-0.80)
sliding_window_size: 3        # Decrease (range: 3-5)
```

### Testing Changes

Use ESPHome logs to see detection scores:

```bash
docker logs -f esphome
# Look for: "Wake word 'hey_freya' detected with probability X.XX"
```

## Troubleshooting

### Training Issues

**Out of Memory (OOM)**
- Reduce `batch_size` to 32 or 16
- Reduce `synthetic_count` to 5000
- Close other applications

**Training Freezes**
- Check GPU drivers if using CUDA
- Try CPU-only training
- Reduce model size to "small"

**Poor Accuracy**
- Add more personal voice samples
- Increase `synthetic_count` to 20000
- Use "heavy" augmentation
- Try different voice models for synthesis

### Deployment Issues

**Model Won't Load**
- Verify both `.tflite` and `.json` files exist
- Check file permissions
- Verify paths in ESPHome config

**Wake Word Not Detected**
- Lower `probability_cutoff` to 0.70
- Check microphone is working
- Verify model is loaded in logs

**Device Out of Memory**
- Remove unused default wake words
- Disable web server
- Use smaller model architecture

## Tips for Best Results

1. **Choose a distinctive phrase** - 2-4 syllables work best
2. **Avoid common words** - Less likely to trigger accidentally
3. **Record in your deployment environment** - Captures room acoustics
4. **Include diverse speakers** - If multiple people will use it
5. **Test extensively before deploying** - Use the notebook's test functions
6. **Start with higher threshold** - Easier to lower than raise
